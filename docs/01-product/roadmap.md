# ZK UI 建议路线图

以下阶段按负责人确认的产品优先级排列，用于安排验证和实现，不代表排期承诺。

| 阶段                  | 目标                              | 主要内容                                                                                                                                                                                                                                      |
|-----------------------|-----------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| 1. 可靠节点操作工作台 | 可靠完成单个目标 znode 的日常操作 | 定位与读取、工作区档案/路径补全、所有合法节点类型与递归操作、明确删除确认、JSON/YAML 查看格式化与高亮、编辑搜索/替换、version CAS、保存前 diff、明确错误、刷新与重连状态可信；SOCKS5 与 HTTP CONNECT 代理；变更审计与完整性校验；本地性能指标 |
| 2. 节点数据维护与迁移 | 提高批量维护、测试和迁移效率      | 脚本/目录管理增强、导入导出、迁移流程、按路径绑定认证身份、冲突恢复、SSH Tunnel、审计增强（保留期与跨设备）                                                                                                                                   |
| 3. 集群运行巡检台     | 汇总并解释 ZooKeeper 集群运行状态 | 多集群巡检、四字命令指标、阈值判断和连接状态汇总                                                                                                                                                                                              |
| 横向工程化            | 支撑各阶段在目标平台交付          | 三平台构建验证、凭据保护、平台适配、托盘、自动更新、签名与公证；按阶段需要逐项实现                                                                                                                                                            |

阶段 1 前应优先完成 Rust 客户端的连接、读取、version 写入、错误返回和重连验证。Watcher 如非首版手动刷新闭环所必需，可后置。三平台关键
WebView 风险应尽早做最小验证，但完整平台集成不应模糊产品优先级。

当前路线图只针对 ZooKeeper。其他中间件工具的交互模式可借鉴；增加 etcd 或其他后端不属于上述阶段，须单独进行产品定位与范围审批。

ACL 权限编辑为后续能力，当前尚未指定所属版本阶段；在确认前不列为首版交付项。
