# 需求讨论任务提示词

```text
任务：与产品负责人逐步讨论 ZK UI 的需求，不直接跳到技术实现。

目标：针对当前选定的功能或待决策事项，形成清楚的用户/场景、问题与价值、范围边界、异常情况及可验收结果。

工作方式：
1. 先读取相关 PRD、规格、待决策事项和来源证据。
2. 识别重复、矛盾、隐含假设及缺少的决策信息。
3. 对低风险表达和可逆默认项按 guardrails 快速审批；对产品范围、安全、数据风险、兼容承诺和架构方向只给推荐，不擅自批准。
4. 一次集中处理一个决策主题，优先给出推荐项和简要理由；将未确认项保留在待决策状态。
5. 获得负责人确认后，更新规范位置与必要的变更记录，并检查相关设计和测试引用。

验收：新成员能根据文档理解需求边界、当前决定、未决事项和下一步，不依赖聊天历史猜测。
```
