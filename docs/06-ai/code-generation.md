# AI 代码生成规则

## 用途

本文件是编码任务的统一入口与重点约束摘要。详细规则分为通用工程规则和 ZK UI 应用规则，按任务范围加载，避免每次编码都读取所有设计材料：

- [通用代码工程规则](code-engineering.md)：语言/语法版本、类型、安全、模块与包边界、依赖、序列化、构建和发布产物。
- [ZK UI 应用代码约束](code-application.md)：Rust/Tauri/Vue 职责边界、ZooKeeper 数据一致性、连接身份隔离、CLI 与产品范围。
- [技术选型调查与验证状态](../05-changes/CHG-0005-technology-route-investigation.md)：依赖候选的证据和未定事项。该调查不是最终依赖清单。

## 编码任务必读规则

所有编码任务先读取本文件，并按 `context-rules.md` 加载相关细则。以下为不可被局部任务提示覆盖的重点：

1. **先看仓库事实**：先读 manifest、工具链版本、锁文件、目录结构、相关实现和测试；现存配置优先于本文候选。不得臆造文件、脚本、依赖或已运行的验证。
2. **版本有唯一来源**：语言 edition/target、最低工具链版本、包管理器和依赖版本应由仓库 manifest、工具链文件和锁文件表达。缺失时不得私自假定或批量升级；提出建议并把相关变更标成待评审。
3. **遵守边界，最小变更**：改动限于任务所需模块；不得擅自新增依赖/抽象层、改变公共协议或扩大产品范围。接口、依赖方向、持久化格式和 IPC 变更需评估兼容与迁移影响。
4. **安全性由可信边界保证**：权限、连接身份、危险写操作和输入校验必须在 Rust 命令/服务边界执行；不能只依赖 UI 隐藏控件或前端校验。
5. **诚实验证**：按任务更新测试和文档；只报告实际执行的检查及其结果。检查未运行时说明原因，不得宣称通过。

明确避免：无需求的泛化/过度封装、仅转发的 wrapper/facade、过早拆 crate/package、万能动态 IPC、全局可变单例、吞错/静默默认、无上限缓存或队列、无条件重试、无关重构和顺手升级。封装、抽象或拆包必须解决已指出的变化点、不变量、多个真实调用方或独立生命周期，并说明成本；没有明确收益就采用更简单的局部实现。

## 稳定提示词

```text
你是 ZK UI 项目的 Rust、Tauri 2 和 Vue 3 工程协作者。先读取 docs/06-ai/code-generation.md，再按 docs/06-ai/context-rules.md 只加载本次代码改动涉及的工程规则、应用规则、需求/设计规格、实现、测试、manifest 与锁文件。

以仓库实际配置为版本和命令的唯一事实来源。未决选型不得伪装成已批准事实；不得擅自新增依赖、升级版本、拆出新 crate/package、改变序列化/IPC 公共协议或扩大产品范围。先做局部、可复核的改动。

严格遵守 ZK UI 应用边界：ZooKeeper 协议、权限、会话和一致性逻辑在 Rust；前端仅通过类型明确的 Tauri IPC 调用核心。所有危险写操作在 Rust 边界重新校验。秘密不得进入日志、普通持久化、前端调试信息或脚本结果。

考虑错误、取消、并发、资源释放、过期响应和跨连接/身份隔离。仅运行适用且已获授权的检查；如未运行，明确说明。完成后报告改动、验证、未决项和风险。
```

## 按任务选择细则

任务类型与加载清单以 [上下文加载规则](context-rules.md) 为准。通常：

- 任何编码：本文件 + `code-engineering.md`。
- Rust/Tauri/连接/节点/CLI：再加载 `code-application.md` 及对应设计或规格。
- Vue 页面/编辑器/交互：再加载 `code-application.md` 中前端部分及对应 UI/功能规格。
- 依赖、版本、构建/发布、跨平台：再加载技术调查、验证路线和实际工具链配置。

不得为了减少读取而省略与变更直接相关的规则；也不得把完整产品文档无差别塞进每个局部任务。
