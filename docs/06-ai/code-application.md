# ZK UI 应用代码约束

本文件只定义本产品的边界和特定交互/数据规则；通用语言、模块、依赖和构建规则见 [code-engineering.md](code-engineering.md)
。产品需求与功能规格优先决定具体行为，AI 不得从本文件推导未确认的产品承诺。

## 1. 当前产品基线与优先级

- 产品是 ZooKeeper 桌面管理工作台，目标平台 Windows、macOS、Linux；已确认技术方向为 Rust + Tauri 2 + Vue
  3。当前依赖及版本仍按技术路线验证，不视为锁定。
- 产品阶段顺序：首版为可靠的单节点操作工作台；其次是节点数据维护与迁移；再其次是集群运行巡检台。
- 当前聚焦 ZooKeeper，不为 etcd 或其他中间件增加通用抽象层。
- 首版支持 ZooKeeper 节点类型的基础创建、读取、修改和删除以及递归操作；所有删除必须明确确认，并展示影响范围。递归操作不是跨节点原子事务，需反映部分成功。
- 首版 ACL 编辑后置；ACL 是否只读展示按当前需求状态处理，不得擅自扩为编辑能力。路径级认证身份绑定属于后续版本。
- JSON/YAML 格式化和高亮是查看表示，不改写原始节点数据。搜索/替换只作用于当前编辑缓冲；远端写入须用户明确保存。
- 二进制/不可解码节点的编辑策略、正式 DSL 语法、ACL 展示等仍有待决事项；实现前先查最新需求记录，不把候选方案当成决定。

## 2. Rust、Tauri 与前端职责

- Rust 核心负责 ZooKeeper 客户端、session/连接池、Watcher、缓存一致性、权限与认证身份、节点读写、CLI 解析执行、本地审计及巡检能力。
- Vue 负责桌面工作台、树/数据呈现、交互、编辑缓冲、命令输入和状态反馈。Vue 不直接实现 ZooKeeper 协议，也不绕过 Rust 访问集群。
- Tauri commands/events 是受校验的 IPC 边界。输入校验、路径规范化、身份与连接绑定、危险操作二次确认、权限判断必须在 Rust
  侧执行；前端负责及时反馈，不作为安全边界。
- IPC payload 应稳定、可序列化、体量有界；长流程定义进度/取消/关联 ID，避免把大节点或大量树节点一次性无界传给 WebView。
- Vue 工具链推荐候选：Vite、TypeScript strict、Vue Router、Pinia、`vue-tsc`
  、Vitest、ESLint。版本、Node、包管理器、具体配置和脚本以验证通过并提交的仓库配置为准。
- Router 管理页面/工作区视图导航；Pinia 只管理边界清晰的跨组件 UI/工作区状态。远端节点数据缓存、认证权限和一致性以 Rust
  核心为准。

### 应避免的应用级做法

- 不在 Vue 组件或 Pinia store 中直接持有 ZooKeeper client、实现协议、缓存权威数据或自行判断 ACL/认证结果。
- 不将 Tauri IPC 做成任意方法名 + `serde_json::Value` 的万能通道；按业务能力定义有限、类型明确的命令和事件，Rust 侧校验所有输入。
- 不为了未来的 etcd/其他中间件支持引入泛化 `StorageProvider`、通用节点模型或多后端工厂；当前先保持 ZooKeeper 语义清晰。
- 不将连接、会话、Watcher、缓存、认证身份压进单个全局 manager/store；按生命周期和隔离边界拆分，并通过显式 ID 关联。
- 不在前端复制 Rust 业务规则作为“快速校验”后又把它当安全保障；前端校验只改善交互，Rust 结果才是权威。
- 不用 watcher 通知直接当作完整变更日志；不以固定 TTL 代替 generation/失效处理；不因断线后 UI 仍有数据就显示为在线或新鲜。

## 3. 连接、认证、缓存与会话

- 每个逻辑连接有明确 ID 和客户端生命周期；不得因一次 UI 点击新建 session，也不得跨连接或认证身份复用缓存、脚本结果、草稿或查询结果。
- 凭据尽量留在 Rust。前端仅接收非秘密身份 ID/展示名；秘密不得写入普通配置、日志、错误、审计、脚本输出或调试信息。
- 不在同一 ZooKeeper session 上静默叠加不同认证身份。连接级认证按批准规格实现；路径级身份映射只能在后续规格批准后实现。
- 缓存键至少包含连接、路径和 session generation；标记读取时间/新鲜度。重连、generation 变化或 Watcher
  失效后，不把旧数据显示为新鲜，必要时拒绝写入并重新读取。
- Watcher 是缓存失效/变化提示，不是完整历史记录。限制订阅范围，处理断线、过期、取消和重新订阅；旧 generation 的事件不得更新当前界面。
- 节点树按需加载，查询请求可取消；排序/搜索/路径跳转不得让过期请求覆盖新选择。树结构缓存与当前节点内容刷新策略分开。
- 避免在 UI 展开每个树节点时无界创建长期 watcher；优先使用有限订阅范围、按需订阅与明确清理，并以实测确定刷新策略。
- 避免用单一“连接成功”布尔值表达 TCP 可达、session 状态、认证状态和数据新鲜度；状态模型需能分别表达这些维度。

## 4. 节点数据与写操作

- ZooKeeper 数据按原始 bytes 处理。解码失败不得静默替换字符、丢字节或在查看时写回。
- 只读格式化不得改变实际存储内容。编辑需有独立缓冲、dirty 状态、撤销/错误处理；只有明确保存才提交原始字节或用户确认的编码结果。
- 写入前基于读取时版本执行 CAS/版本检查；冲突明确呈现，不自动覆盖或盲目重试。修改前可展示 diff 和目标路径/连接，符合对应规格。
- 删除、递归操作、批量写入属于危险操作。Rust 再校验目标、范围和确认信息；结果区分已完成、失败、未执行。不能把多节点操作伪装成原子提交。
- 错误应区分无权限、节点不存在、会话断开、版本冲突、巡检不可用、超限和数据解码失败，不得用同一“请求失败”混淆可恢复行为。
- 避免读后无条件覆盖、冲突后自动重试写入、将格式化后的 JSON/YAML 直接当原始 bytes 回写，以及将部分成功的递归操作报告为整体成功。
- 避免在未定义数据大小上限/预览策略前一次性把超大节点内容复制进 Rust、IPC、前端 store 和编辑器多份缓冲。

## 5. CLI 与脚本

- CLI 是面向 ZooKeeper 的应用命令，不是系统 shell。禁止通过 shell、cmd、PowerShell、JavaScript eval 执行输入。
- 脚本按顺序执行；首条失败立即停止。换行和分号为命令终止符，字符串内分号、引号、转义、注释、空行等按正式 DSL 规格实现，不能靠空格切分解析。
- 执行前固定并显示目标连接/身份；写操作摘要必须从实际解析 AST 产生，并在执行边界校验，不能只由 UI 拼造。
- 多次查询的结果按本次 run/session 保留并可折叠查看；运行结束或会话隔离边界不得跨身份残留结果。
- 自动补全按所需路径层级请求；新输入取消过时请求，避免延迟响应覆盖候选或请求无界堆积。
- 避免先把脚本拆成行/空格字符串再执行；先按明确 grammar/tokenizer 解析为带源位置的 AST，再做目标绑定、摘要展示、校验和执行。
- 避免“预览摘要”和真正执行路径分别解析命令；摘要必须由待执行的同一 AST 派生，防止展示与执行不一致。

## 6. 本地工作区与平台能力

- 连接配置、最近路径、展开状态等本地工作区信息与远端 ZooKeeper 数据分开管理；只持久化产品明确需要保留的内容。
- 普通偏好配置与秘密凭据分开存储。没有可用安全凭据存储时明确提示并定义可用行为，禁止静默降级为明文。
- 平台差异通过明确适配层处理，不在业务逻辑中散布平台判断。Tauri capability 最小化，文件/系统 API 按任务授权范围开放。
- Windows/macOS/Linux 的菜单、快捷键、对话框、WebView、凭据服务及打包差异按平台验证；桌面三平台的行为一致性不等于像素完全一致。

## 7. 关键质量场景

按实际变更覆盖相关场景：CAS 冲突、递归删除部分失败、认证拒绝、连接断开/重连 generation 变化、Watcher 失效、旧响应竞态、原始
bytes 保真、JSON/YAML 只读格式化、脚本首错停止、查询结果身份隔离、凭据脱敏和危险操作二次确认。

场景执行与测试计划见 `docs/04-test/`；验证路线中的计划项目不能表述为已完成测试。
