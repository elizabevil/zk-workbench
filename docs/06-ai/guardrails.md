# AI 决策与快速审批边界

## 可快速审批的事项

AI 可在不打破已确认需求、架构和安全约束的前提下，直接选择并记录以下低风险默认项：

- 文档标题、章节顺序、术语一致性、重复内容合并和格式细节。
- 不改变用户可见行为的局部实现建议，例如内部命名、模块拆分草案和非公开接口组织。
- 可逆、低成本的验证顺序、实验参数初值和原型范围；必须标为实验值，不写成产品承诺。
- 对已确定功能的验收描述补全，不改变功能范围或隐含新增能力。

快速审批记录使用简短格式：`AI 快速审批：<选择>；依据：<现有约束/证据>；影响：<范围>；可逆性：可逆；状态：已采纳（AI 授权范围）`
。若项目变更规范要求使用 CHG 或 ADR，则按对应规范记录，不另造记录格式。

## 必须由产品负责人确认

AI 不得自行批准或将以下事项写成已确认基线：

- 产品定位、目标用户、产品边界、首版范围、用户可见行为或验收承诺。
- 认证、凭据保存、权限边界、隐私、审计、安全策略或数据保留规则。
- 删除、覆盖、批量写入、递归操作等可能导致数据损失的行为。
- 兼容性承诺、最低平台/服务端版本、协议或公共接口稳定性承诺。
- Rust 客户端选型、共享 session 策略、架构方向改变或较大技术债务。
- 需要新增外部服务、持续成本、部署责任或发布承诺的事项。
- 证据不足且不同选项会明显改变产品价值、用户风险或成本的事项。

此类事项可以给出一个推荐方案和其他备选项；文件状态保持 `proposed` 或规范中对应的待决状态，并列入待决策清单。

## 测试与脚本必须落盘

任何验证结论都必须能由仓库内容复现，不允许只存在于对话或临时目录。

1. **必须有仓库内文件**：每个验证结论对应一个可执行文件——测试（`crates/zkui-core/tests/`、`*_test.rs`、`*.spec.ts`）、脚本（
   `test/`、`scripts/`）、环境编排（`test/env/`）或 justfile 配方。只在聊天里出现的命令不算。
2. **临时目录不算落盘**：在 `/tmp`、临时 worktree 或临时容器里写过的脚本、compose
   文件、fixture、日志片段，只要参与了结论，必须先复制进仓库并提交，再引用其仓库路径。
3. **代码与脚本文件必须保留**：禁止「测完即删」「只贴代码不落文件」；对照实现、基准、复现脚本都按 `_common.md` 第 7 节保留。
4. **回复必须可复现**：给出文件路径、用例名与复现命令；未执行的验证必须说明原因，不得写成通过。
5. **违反处置**：立即停止，补交文件或撤回结论，并说明已经受影响的判断。

## 证据与推论

- 官方文档、版本化 API、实测结果属于可引用证据；营销页面、社区讨论或 AI 记忆不能单独支撑高影响决定。
- 引用必须足以让新人找到原始来源，并标明资料版本/访问日期（若规范要求）。
- 从来源推导出的产品或架构建议应明确标为推论。
- 性能、并发安全、重连、Watcher 恢复和跨平台行为等依赖版本或环境的能力必须实测，不能仅凭类型/API 存在而批准。

## 冲突处理

若本规则与用户当前明确指令冲突，以用户指令为准；若项目规范和旧项目文档冲突，指出冲突并以规范文件为准，除非负责人明确批准偏离并记录变更。
