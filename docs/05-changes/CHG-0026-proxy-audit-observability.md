# CHG-0026：代理、变更审计与可观测纳入首版

## 决策

1. **代理**：首版支持 **SOCKS5 与 HTTP CONNECT**；SSH Tunnel 维持第二阶段。实现为 core 内传输抽象 + 本地中继，ZooKeeper 客户端连本地端口。
2. **审计**：只记录**变更操作**（创建、修改、删除、ACL 修改），不记录读取；SQLite + 哈希链，提供完整性校验、节点历史与全局时间线。
3. **可观测**：默认不外发；**OpenTelemetry 导出由用户在应用内显式开启并可关闭**；本地指标固定采集延迟分位、请求计数、缓存命中/失效与重连次数。

## 语句变更

| 原语句 | 处理 | 新语句 |
|---|---|---|
| `REQ-AUTH-PRIV-001`（一律不外发） | supersede | `REQ-OPS-OBS-001`（默认不外发，显式开启 OTel） |
| `REQ-OPS-AUDIT-001`（`#deferred`） | supersede | `REQ-OPS-AUDIT-003`（仅变更操作，字段完整） |
| `REQ-OPS-AUDIT-002`（`#deferred`） | supersede | `REQ-OPS-AUDIT-004`（本地持久、时间线、哈希链、非合规） |
| — | 新增 | `REQ-OPS-AUDIT-005`（不阻塞、失败可见） |
| — | 新增 | `REQ-OPS-OBS-002`（本地性能指标） |
| — | 新增 | `REQ-CONN-PROXY-001..003` |

## 架构决定

- `dec/proxy.md`：传输抽象 + 本地中继；代理凭据复用四档保存（`DEC-070`、`DEC-071`）。
- `dec/observability.md`：审计 SQLite 哈希链（`DEC-080`）；OTel 默认关闭（`DEC-081`）；指标范围（`DEC-082`）。

## 路线与切片

- 路线图阶段 1 增加：SOCKS5/HTTP CONNECT 代理、变更审计与完整性校验、本地性能指标；阶段 2 的「本地操作追溯」上移，改为「审计增强」。
- 切片调整为：S2 代理 → S3 审计基础 → S4 树 → S5 节点读取 → S6 编辑保存（接入审计）→ S7 创建删除（接入审计）→ S8 指标与 OTel 开关 → S9 命令区 → S10 脚本。

## 考虑点（待落地）

1. **审计性能**：异步写队列与批量提交；需基准证明审计写入对 set/create/delete 延迟的影响可接受（<5%）。
2. **哈希链起点**：每条连接/每天/全局一条链，需要定义；建议全局单链，便于完整性校验。
3. **保留期与导出**：默认保留期、导出格式（JSONL/SQLite 副本）、清理策略。
4. **代理错误分类**：需要新增 `proxy_*` 错误前缀，避免与 `zk_*` 混淆。
5. **OTel 依赖**：`opentelemetry-otlp` 走 feature 隔离，默认不编译，避免包体与隐私默认值问题。
6. **配置 UI**：代理与 OTel 设置页；OTel 开启时需明确提示「将向指定端点发送数据」。
7. **凭据一致性**：代理凭据与集群凭据共用 keyring 与四档策略，界面复用同一组件。

## 后续方向

- 审计：时间线 UI、按路径/连接筛选、导出、跨设备汇总（阶段 2）。
- 代理：SSH Tunnel（阶段 2）、代理健康检查与自动重连提示。
- 可观测：应用内性能面板、OTLP 指标导出、与团队 Collector 的对接说明。

## 非目标（Non-Goals）

1. 不把读取操作写入审计。
2. 不宣称合规审计或覆盖其他客户端操作。
3. 不在首版实现 SSH Tunnel。
4. 不默认外发任何遥测。
5. 不做跨设备审计同步。

## 候选方案与权衡（Alternatives & Trade-offs）

**审计用 JSONL 追加文件**：查询与分页时间线要自己实现，哈希链也需额外索引；改用 SQLite。

**OTel 默认开启**：与隐私默认值冲突，且会给用户带来未预期外发；改为显式开启。

**代理直接修改客户端连接器**：依赖库内部实现；改为本地中继，零侵入且可复用到 SSH。
