# CHG-0020：Spike A 首轮执行记录

## 环境

| 项 | 值 |
|---|---|
| 服务端 | 192.168.11.5:2181 |
| 版本 | ZooKeeper 3.9.5（`srvr` 输出，built 2026-02-11） |
| 角色 | follower |
| 客户端 | zookeeper-client 0.11.2（tokio feature），测试见 `crates/zkui-core/tests/spike_client_a.rs` |

## 命令

```bash
cd project
CARGO_HOME=$PWD/.cargo-home \
ZK_SPIKE_ENDPOINT=192.168.11.5:2181 \
cargo test -p zkui-core --test spike_client_a -- --ignored --nocapture --test-threads=1
```

通过项：连接与会话状态、持久节点 CRUD、CAS 与版本冲突、临时/顺序/容器节点、子节点与 Stat、ACL 读取、一次性 Watcher、非空节点删除返回 `NotEmpty`。

未覆盖：断线重连、会话过期、认证失败、并发访问、3.4/3.5 互操作、Tauri 集成（`TEST-001` 仍不完整）。

## 中间态异常与恢复

首次执行后的一段时间内，新建连接持续返回 `Timeout`（客户端 6 秒超时），期间：

- TCP 端口可达，`srvr` 有响应；
- `mntr`、`stat`、`cons` 被服务端四字命令白名单拒绝，无法读取存活连接与集群状态；
- 节点数与 Zxid 在两次采样间未变化。

随后未经改动重试即恢复，连接与用例正常。判断为服务端瞬时会话层异常，未做服务端配置变更。

清理用例删除了首次执行遗留的 `/spike-types-*` 节点；随后再跑一轮仍为 8/8 通过，`srvr` 显示节点数从 80 回到 78，根下无 `spike-` 前缀残留。

## 遗留数据

无。`node_types_ephemeral_sequential_container` 已改为递归清理，`cleanup_spike_nodes` 兜底；两轮执行后根下无本测试创建的节点。

## 影响

- `DEC-002`（客户端选型）仍为 `proposed`：单实例、单版本、一轮通过不足以定案。
- 3.4/3.5 兼容矩阵与断线/会话过期场景仍需在可用环境补测。

## 非目标（Non-Goals）

1. 不据此宣布 zookeeper-client 为最终选型。
2. 不修改服务端配置或四字命令白名单。
3. 不覆盖 Tauri 集成与并发压测。
4. 不在本记录中结论化集群异常原因。
5. 不清理非本测试创建的节点。

## 候选方案与权衡（Alternatives & Trade-offs）

**以单实例通过作为选型依据**：样本不足且未覆盖会话与兼容性；被拒绝，维持 `proposed`。

**跳过 3.4/3.5 直接进入实现**：与 `REQ-CONN-COMPAT-001` 冲突，后续返工成本高；被拒绝。

## 验证

命令与输出见上；测试文件与版本已在仓库内（`crates/zkui-core/tests/spike_client_a.rs`、`project/Cargo.lock`）。
