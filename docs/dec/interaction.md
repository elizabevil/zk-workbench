# 交互与布局决策

本文件只记录交互 **选择与理由**；具体行为由 `req/` 中的语句定义，此处不复述正文。

DEC-010 status: proposed updated: 2026-11-02
选择：工作台采用左侧连接/节点树、中间标签式数据区、右侧可折叠 Stat/ACL 检查器、底部可折叠命令与输出区的信息架构。
依据：CHG-0004 F 项已确认；DataGrip 仅作交互参考，不复制视觉。
推翻条件：窄窗口可用性或键盘导航实测不可接受。
影响：布局类 REQ 待 UI 域迁移时定义；当前无 REQ 变更。

DEC-011 status: proposed updated: 2026-11-02
选择：删除采用「单一入口 + 显式递归勾选 + 预览 + 分项报告」的 D1 方案，并提供「仅重试失败子树」。
依据：CHG-0006 对 D1/D2 的比较；D2（三个并列删除入口）因影响范围难以表达被拒。
推翻条件：实测显示预览遍历成本不可接受，或用户研究一致要求独立入口。
影响：行为由 REQ-NODE-DEL-001 至 REQ-NODE-DEL-008 定义。

DEC-012 status: proposed updated: 2026-11-02
选择：创建采用「不静默创建父链 + 显式勾选创建父路径 + 顺序节点路径回显 + 临时节点会话提示」的 C1 方案。
依据：CHG-0006 对 C1/C2 的比较；C2（默认递归创建父链）因误操作风险被拒。
推翻条件：可用性测试显示用户频繁需要父链创建且显式勾选成本过高。
影响：行为由 REQ-NODE-CREATE-001 至 REQ-NODE-CREATE-007 定义。
