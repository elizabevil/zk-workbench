# 产品验证路线图

## 目的

当前项目处于需求讨论阶段。本路线图先定义未来要回答的问题、验证方法和进入条件，不表示已经执行验证或获得通过结果。每次实际验证应记录版本、环境、步骤、观测数据和结论，链接到对应 TEST/CHG 记录。

## 阶段 0：需求与验证方案准备

**当前阶段。**

- 确认首版核心任务、边界和成功标准。
- 确认目标 ZooKeeper 版本、连接认证方式、目标操作系统和典型数据规模。
- 为每个高风险假设定义可复现的实验、测试环境和通过/失败判据。
- 未确认测试环境和判据前，不声称性能、兼容或安全能力已验证。

## 阶段 1：可靠单节点操作可行性

进入条件：阶段 0 的关键环境、需求和验收判据已确定。

验证主题：

1. 按 `05-changes/CHG-0005-technology-route-investigation.md` 的 Spike A 对候选 Rust ZooKeeper 客户端作同一矩阵对比；通过后再锁定依赖。
2. 候选客户端的连接、读取、所有支持节点类型的创建、修改、删除、version CAS 与错误映射。
3. 递归删除的确认、影响范围预览、部分失败报告和恢复路径。
4. 连接中断、会话过期和重连时的界面状态及数据新鲜度处理。
5. 按 Spike B 对编辑器候选作 WebView/功能/体积对比；验证 JSON/YAML 查看格式化、高亮、搜索/替换草稿与保存行为，格式化不得改变原始内容。
6. 不可解码字节的只读预览/完整替换候选流程及 version 冲突保护。
7. 按 Spike C 验证三平台凭据后端与无凭据服务环境的行为。
8. 多连接配置保存和单活动连接基线；需要时再测试并发 session 资源。
9. Windows、macOS、Linux 的最小构建及关键 WebView/编辑器体验。
10. 按 `05-changes/CHG-0005-technology-route-investigation.md` 验证前端工具链组合：Vite/Vue 插件、TypeScript strict、`vue-tsc`、Vue Router（含 Tauri 路由刷新/深链策略）、Pinia、Vitest/组件测试、ESLint 与格式化；同时确认兼容的 Node.js 版本、包管理器和锁文件策略。

阶段出口：首版节点操作闭环的验收场景可复现，失败边界与限制已记录；未达标项有明确处置决定。

## 阶段 2：数据维护与迁移

进入条件：阶段 1 的可靠节点操作基线通过产品评审。

验证主题：CLI 语法/自动补全负载、脚本解析边界（换行、分号、引号、转义）、单行与顺序执行、首错停止、查询结果体量与折叠展示、脚本文件访问范围、导入导出正确性、按路径身份映射与独立 session 隔离。

阶段出口：测试/迁移流程可重复执行，错误定位与结果追溯足够明确，认证身份切换不串用。

## 阶段 3：集群巡检

进入条件：至少一个真实使用场景确认巡检指标和判定阈值。

验证主题：四字命令可用性、平台/服务端差异、并发轮询负载、阈值误报/漏报、巡检不可用与集群故障的区分。

阶段出口：指标含义、数据更新时间、阈值配置和不可用状态都可解释。

## 验证记录约定

每个验证记录至少包含：目标问题、来源假设、软件与依赖版本、服务端/操作系统环境、步骤、原始数据或日志链接、通过标准、结果、限制和决策影响。计划状态与验证结果状态分开维护。
